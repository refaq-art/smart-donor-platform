# منصة إدارة مشاريع ومنح الجمعيات الخيرية

منصة ويب متكاملة مخصصة لموظفي الجمعيات الخيرية المسؤولين عن إعداد المشاريع ورفع طلبات الدعم والمنح إلى الجهات المانحة. تساعد المنصة على إدارة المشاريع، رصد فرص التمويل، إدارة الجهات المانحة، إعداد طلبات المنح خطوة بخطوة، متابعة حالتها، وتوليد التقارير — مع مساعد ذكاء اصطناعي مدمج لصياغة ومراجعة المحتوى.

> **ملاحظة حول الإصدار السابق**: كان هذا المستودع يحتوي على نموذج أولي بسيط (صفحة HTML واحدة تعمل بالكامل داخل المتصفح وتحفظ البيانات في LocalStorage). تمت إعادة بناء المنصة بالكامل لتصبح تطبيق ويب حقيقي بقاعدة بيانات وخادم ونظام صلاحيات، مع الإبقاء على نفس الفكرة والهوية العامة (جمعية رفاق الخيرية كبيانات تجريبية).

---

## 1. التقنيات المستخدمة ولماذا

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة والخادم | **Next.js 14 (App Router) + React 18 + TypeScript** | إطار عمل مفتوح المصدر ناضج يجمع الواجهة والـ API في مشروع واحد، يدعم SSR لأداء أفضل، ومناسب جدًا لتطبيقات لوحات التحكم بمنطق خادم كثيف (Server Actions). |
| التنسيق | **Tailwind CSS** | نظام تصميم مرن يسهّل بناء واجهة مؤسسية متجاوبة وموحدة بسرعة، ويدعم RTL بسهولة. |
| قاعدة البيانات | **SQLite عبر Prisma ORM** | قاعدة بيانات ملف واحد لا تحتاج أي خادم أو تكلفة، مثالية للتشغيل المحلي فورًا، مع إمكانية الترقية لاحقًا إلى PostgreSQL/MySQL بتغيير سطر واحد في المخطط لأن Prisma يجرد طبقة الاتصال بقاعدة البيانات. |
| المصادقة | **جلسات JWT موقّعة (مكتبة jose) + bcrypt** | حل خفيف ومملوك بالكامل للمشروع (بدون الاعتماد على خدمة خارجية أو مزود مصادقة سحابي)، يعمل بأمان مع Edge Middleware لحماية الصفحات. |
| الذكاء الاصطناعي | **طبقة مزوّد مستقلة (Mock + أي واجهة متوافقة مع OpenAI)** | تفصل منطق الذكاء الاصطناعي عن الواجهة، تعمل بدون أي مفتاح افتراضيًا (وضع تجريبي محلي)، ويمكن ربطها بأي مزود مجاني أو مفتوح المصدر لاحقًا. |
| الأيقونات | **lucide-react** | مكتبة أيقونات مفتوحة المصدر خفيفة وشائعة الصيانة. |

كل هذه التقنيات مفتوحة المصدر، ولا تتطلب أي اشتراك مدفوع لتشغيل المنصة محليًا.

### لماذا لم يُستخدم مخطط Lovable الأصلي؟
كان المشروع المرفق (Lovable / TanStack Start + Supabase Cloud) موجّهًا لإدارة علاقات الداعمين بشكل عام (Donor CRM) ومرتبطًا ببنية سحابية خاصة بـ Lovable (مصادقة سحابية، Supabase مُدار). تطلبت المتطلبات الجديدة منصة **لإدارة المشاريع وطلبات المنح** لموظفي الجمعيات تحديدًا، بصلاحيات أدوار، وسير عمل مختلف تمامًا لحالة الطلبات، وقابلية تشغيل محلي كامل دون أي خدمة سحابية مدفوعة. لذلك أُعيد البناء من الصفر بمخطط بيانات وواجهات مطابقة للمتطلبات، مع الإبقاء على الروح العامة (هوية جمعية خيرية، فكرة رصد الفرص ومطابقتها، الخطابات كمرفقات).

## 2. بنية المشروع

```
src/
  app/
    (app)/                  # كل الصفحات المحمية (تتطلب تسجيل دخول)
      layout.tsx            # القالب العام: الشريط الجانبي + الشريط العلوي
      dashboard/             # لوحة التحكم
      projects/              # إدارة المشاريع (قائمة/إنشاء/تفاصيل/تعديل)
      opportunities/          # إدارة فرص التمويل
      donors/                 # إدارة الجهات المانحة
      applications/            # طلبات المنح (معالج متعدد الأقسام + متابعة الحالة)
      reports/                # التقارير القابلة للطباعة والتصدير
      settings/users/          # إدارة المستخدمين (لمدير النظام فقط)
    actions/                 # Server Actions (منطق الخادم: إنشاء/تعديل/حذف/تغيير حالة)
    login/                   # صفحة الدخول
    layout.tsx, globals.css  # القالب الجذري و RTL والخطوط
    icon.tsx                 # أيقونة المنصة (تُولَّد برمجيًا، بدون شعار خارجي)
  components/                # مكونات واجهة قابلة لإعادة الاستخدام
  lib/
    ai/                      # طبقة مزوّد الذكاء الاصطناعي (mock + openai-compatible)
    prisma.ts, auth.ts, roles.ts, constants.ts, completion.ts, utils.ts, upload-file.ts
  middleware.ts              # حماية المسارات على مستوى الـ Edge
prisma/
  schema.prisma              # مخطط قاعدة البيانات الكامل
  seed.ts                    # سكربت البيانات التجريبية العربية
public/uploads/              # مجلد تخزين الملفات المرفوعة محليًا
```

### فصل الطبقات
- **العرض (UI)**: مكونات `src/components` و صفحات `src/app/(app)/**/page.tsx`.
- **المنطق/الخادم**: `src/app/actions/*.ts` (تحقق من الصلاحيات، تحقق من صحة البيانات عبر Zod، عمليات قاعدة البيانات، تسجيل النشاط).
- **البيانات**: `prisma/schema.prisma` عبر `src/lib/prisma.ts`.

## 3. الوحدات المنجزة

1. **لوحة التحكم**: عدد المشاريع، فرص التمويل المتاحة، الطلبات قيد الإعداد/المرسلة/المقبولة/المرفوضة، نسبة القبول، المواعيد النهائية القريبة (خلال 14 يومًا)، تنبيهات المعلومات الناقصة لكل طلب مع نسبة اكتماله.
2. **إدارة المشاريع**: إنشاء/تعديل/حذف/تكرار، مشكلة، أهداف عامة وتفصيلية، فئة مستفيدة ونطاق جغرافي، أنشطة/مخرجات/نتائج/مؤشرات أداء (حقول ديناميكية قابلة للإضافة والحذف)، جدول زمني وميزانية تفصيلية، رفع مرفقات، حفظ كمسودة.
3. **فرص التمويل**: إضافة/تعديل/حذف، ربط بجهة مانحة أو اسم حر، ربط بمشروع، شروط ومتطلبات، تاريخ بداية ونهاية، رابط تقديم، حالة (مفتوحة/تحت المتابعة/مغلقة)، بحث وتصفية وترتيب، تنبيه بصري عند اقتراب الموعد النهائي (14 يومًا).
4. **الجهات المانحة**: بيانات الجهة ومجالات الدعم وشروط التمويل وبيانات التواصل وحالة العلاقة، الفرص والمشاريع المرتبطة، ملاحظات ومرفقات.
5. **طلبات المنح**: معالج بأقسام (تبويبات) يغطي كل العناصر الـ 16 المطلوبة (الملخص التنفيذي، تعريف الجمعية، وصف المشكلة، المبررات، الأهداف، الفئة المستفيدة، خطة التنفيذ، الأنشطة، المخرجات، النتائج، المؤشرات، إدارة المخاطر، الاستدامة، الجدول الزمني، الميزانية، متطلبات الجهة المانحة) + نسبة اكتمال محسوبة تلقائيًا وقائمة بالعناصر الناقصة.
6. **متابعة الطلبات**: 8 حالات (مسودة، تحت المراجعة الداخلية، جاهز للإرسال، تم الإرسال، مطلوب استكمال، مقبول، مرفوض، مؤجل) مع سجل كامل لكل تغيير (من/إلى، ملاحظة، الخطوة التالية، المستخدم، التاريخ).
7. **التقارير**: 8 تقارير (المشاريع، فرص التمويل، الطلبات المرسلة، نسب القبول، الجهات المانحة، المواعيد النهائية، الميزانيات، أداء الموظفين) قابلة للطباعة (`window.print`) وللتصدير كملف CSV متوافق مع Excel (بترميز UTF-8 مع BOM لدعم العربية).
8. **مساعد الذكاء الاصطناعي**: مدمج داخل نماذج المشاريع والطلبات (صياغة الملخص التنفيذي، تحسين وصف المشكلة، اقتراح أهداف/أنشطة/مخرجات/مؤشرات، مراجعة الترابط والتناقض، إعادة الصياغة الرسمية، تلخيص شروط الفرصة، المقارنة مع شروط الجهة المانحة، تقييم جاهزية الطلب). **لا يختلق بيانات غير موجودة** — يوضح دائمًا عند نقص المعلومات ويطلب إدخالها.
9. **الصلاحيات**: 4 أدوار (مدير النظام، مدير الجمعية، مسؤول المنح، مراجع) مع حماية فعلية على مستوى الصفحات والإجراءات (وليس فقط الواجهة).
10. **رفع الملفات**: مرفقات للمشاريع والطلبات والجهات المانحة، تحقق من النوع (PDF/Word/Excel/صور) والحجم (10 ميجابايت افتراضيًا) على الخادم.

### ما لم يُنفَّذ / قيود متبقية
- لا يوجد بحث تلقائي (Web Crawling) عن فرص تمويل جديدة من الإنترنت — يتم تسجيل الفرص يدويًا كما طُلب صراحة أن الميزات الأساسية لا تعتمد على خدمة مدفوعة أو زحف تلقائي.
- إشعارات البريد الإلكتروني للمواعيد النهائية غير مُفعّلة (تظهر كتنبيهات داخل المنصة فقط) — يمكن إضافتها لاحقًا عبر خدمة بريد مجانية (مثل Resend المجاني أو SMTP).
- تصدير التقارير حاليًا بصيغة CSV (تُفتح مباشرة في Excel) وطباعة المتصفح لصيغة PDF، بدون توليد PDF مخصص من الخادم.
- ميزات الذكاء الاصطناعي الحقيقية (غير التجريبية) تتطلب مفتاح API من مزود خارجي (اختياري تمامًا، راجع القسم 6).

## 4. التثبيت والتشغيل محليًا

### المتطلبات
- Node.js 18 أو أحدث (تم البناء والاختبار على Node 22).
- npm (مضمن مع Node).
- لا حاجة لأي قاعدة بيانات خارجية أو حساب سحابي.

### خطوات التشغيل

```bash
# 1. تثبيت الحزم
npm install

# 2. إعداد متغيرات البيئة
cp .env.example .env
# لا حاجة لتعديل أي قيمة للتشغيل المحلي الأساسي

# 3. إنشاء قاعدة البيانات (SQLite محلي، ملف dev.db)
npm run db:push

# 4. تعبئة البيانات التجريبية العربية (جمعية، مستخدمون، مشاريع، فرص، طلبات)
npm run db:seed

# 5. تشغيل خادم التطوير
npm run dev
```

افتح المتصفح على: **http://localhost:3000**

### أوامر قاعدة البيانات
```bash
npm run db:push    # مزامنة مخطط Prisma مع قاعدة البيانات
npm run db:seed    # تعبئة/إعادة تعبئة البيانات التجريبية (تحذف التجريبية القديمة أولًا)
npm run db:reset   # إعادة إنشاء القاعدة من الصفر + تعبئة تجريبية (للتطوير فقط)
```

### البناء للإنتاج
```bash
npm run build
npm run start
```

## 5. بيانات الدخول التجريبية

بعد تشغيل `npm run db:seed`، يمكن الدخول بأي من الحسابات التالية (تظهر أيضًا كأزرار سريعة في صفحة الدخول):

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| مدير النظام | `admin@refaq.org` | `Passw0rd!` |
| مدير الجمعية | `manager@refaq.org` | `Passw0rd!` |
| مسؤول المنح | `officer@refaq.org` | `Passw0rd!` |
| مراجع | `reviewer@refaq.org` | `Passw0rd!` |

تشمل البيانات التجريبية: جمعية "رفاق الخيرية"، 4 مستخدمين بأدوار مختلفة، 4 مشاريع، 4 جهات مانحة، 5 فرص تمويل (بعضها بمواعيد قريبة لاختبار التنبيهات)، و6 طلبات منح بحالات مختلفة مع سجل متابعة كامل. جميع السجلات التجريبية موسومة داخليًا (`isDemo`) ويمكن حذفها بالكامل أو استبدالها في أي وقت بإعادة تشغيل `npm run db:seed` أو `npm run db:reset` دون أن تختلط ببيانات إنتاجية حقيقية تُدخل لاحقًا (التي لا تحمل هذا الوسم).

## 6. متغيرات البيئة

ملف `.env.example` (انسخه إلى `.env`):

```bash
DATABASE_URL="file:./dev.db"       # قاعدة بيانات SQLite محلية
AUTH_SECRET="..."                   # مفتاح تشفير الجلسات — غيّره في الإنتاج
AI_PROVIDER="mock"                  # mock | openai
AI_API_KEY=""                       # مطلوب فقط عند AI_PROVIDER=openai
AI_BASE_URL=""                      # رابط API بديل (Groq/Ollama/Together...)
AI_MODEL="gpt-4o-mini"              # اسم النموذج
MAX_UPLOAD_MB="10"                  # الحد الأقصى لحجم المرفقات
```

**لا يوجد أي مفتاح أو سر داخل الكود المصدري** — كل القيم الحساسة تُقرأ من متغيرات البيئة فقط، وملف `.env` مستثنى من Git عبر `.gitignore`.

## 7. تشغيل ميزات الذكاء الاصطناعي

المنصة تعمل بكامل ميزاتها **بدون أي مفتاح API** عبر "الوضع التجريبي" (`AI_PROVIDER=mock`، وهو الافتراضي). في هذا الوضع تُنتَج اقتراحات وصياغات مبنية على المدخلات الفعلية فقط (بدون اختلاق بيانات)، مع رسالة توضيحية أن النتيجة تجريبية.

### لتفعيل مزود ذكاء اصطناعي حقيقي
الطبقة مبنية على واجهة متوافقة مع OpenAI Chat Completions API، فتعمل مع أي مزود يوفرها، مثل:

- **Groq** (له خطة مجانية سخية وسرعة عالية): `AI_BASE_URL="https://api.groq.com/openai/v1"`, `AI_MODEL="llama-3.1-8b-instant"`
- **Ollama** (تشغيل نموذج محليًا مجانًا بالكامل): ثبّت [Ollama](https://ollama.com)، شغّل `ollama pull llama3.1`، ثم اضبط `AI_BASE_URL="http://localhost:11434/v1"` و `AI_API_KEY="ollama"` (أي قيمة غير فارغة)
- **OpenAI الرسمي**: اترك `AI_BASE_URL` فارغًا واضبط `AI_API_KEY` بمفتاحك

ثم اضبط `AI_PROVIDER="openai"` في `.env` وأعد تشغيل الخادم.

### معالجة الأخطاء
عند انتهاء الحد المجاني (429)، انقطاع الاتصال، أو أي خطأ من المزود، تتحول المنصة تلقائيًا إلى نتيجة تجريبية بديلة مع رسالة توضح السبب — لا يتعطل أي إجراء في المنصة بسبب فشل خدمة الذكاء الاصطناعي.

## 8. الصلاحيات والأدوار

| الدور | الصلاحيات |
|---|---|
| **مدير النظام** (ADMIN) | كل الصلاحيات + إدارة المستخدمين والأدوار |
| **مدير الجمعية** (ORG_MANAGER) | إشراف كامل على المشاريع/الفرص/الجهات/الطلبات + حذف السجلات + التقارير |
| **مسؤول المنح** (GRANTS_OFFICER) | إنشاء وتعديل المشاريع والفرص والجهات والطلبات، تغيير حالة الطلبات |
| **مراجع** (REVIEWER) | عرض جميع البيانات دون تعديل مباشر للمحتوى، مع إمكانية تغيير حالة الطلب (اعتماد/إرجاع) وكتابة ملاحظات المراجعة |

تُطبَّق هذه الصلاحيات على مستوى **الخادم** (داخل كل Server Action) وليس فقط بإخفاء عناصر الواجهة، لمنع أي التفاف على الحماية.

## 9. الاختبارات

### اختبارات E2E آلية (Playwright)

يحتوي المستودع على مجموعة اختبارات آلية حقيقية (تشغّل متصفح Chromium فعليًا ضد الخادم) في `tests/e2e/`، تغطي المسارات الأساسية للمنصة:

| الملف | يغطي |
|---|---|
| `auth.spec.ts` | تسجيل الدخول بكل الأدوار الأربعة، بيانات دخول خاطئة، حماية المسارات، تسجيل الخروج، ظهور/إخفاء رابط إدارة المستخدمين حسب الدور |
| `projects.spec.ts` | إنشاء مشروع بحقوله الديناميكية، عرضه، تعديله، تكراره، البحث في القائمة، منع المراجع من الإنشاء |
| `donors-opportunities.spec.ts` | إنشاء جهة مانحة، إنشاء فرصة تمويل مرتبطة بمشروع وجهة، ظهورها في صفحتيهما، التصفية حسب الحالة |
| `applications.spec.ts` | إنشاء طلب منحة، تعبئة أقسامه عبر التبويبات، ارتفاع نسبة الاكتمال، بقاء البيانات بعد إعادة التحميل، مساعد الذكاء الاصطناعي (وضع تجريبي)، تغيير الحالة وتسجيلها في سجل المتابعة |
| `attachments.spec.ts` | رفع مرفق مسموح به ونجاحه، رفض ملف بامتداد غير مدعوم برسالة عربية واضحة |
| `reports.spec.ts` | التنقل بين التقارير، تصدير CSV فعليًا |
| `users.spec.ts` | إضافة مستخدم جديد (كمدير نظام)، منع حذف الحساب الحالي |

**تشغيل الاختبارات محليًا:**

```bash
npm run test:e2e        # تشغيل كل الاختبارات في الطرفية
npm run test:e2e:ui     # تشغيلها بواجهة Playwright التفاعلية
```

يقوم الإعداد (`playwright.config.ts`) تلقائيًا بإعادة تهيئة قاعدة البيانات وتعبئتها بالبيانات التجريبية، ثم تشغيل خادم التطوير، قبل تنفيذ الاختبارات — لا حاجة لأي إعداد يدوي مسبق. عند التشغيل لأول مرة قد تحتاج لتثبيت متصفح Chromium الخاص بـ Playwright:

```bash
npx playwright install chromium
```

> إن كانت بيئتك توفر متصفح Chromium مثبّتًا مسبقًا في مسار مخصص (كبعض بيئات CI)، مرّر مساره عبر `PLAYWRIGHT_CHROMIUM_PATH=/path/to/chromium npm run test:e2e` بدل تثبيت نسخة جديدة.

هذه المجموعة اكتشفت فعليًا خللًا حقيقيًا أثناء التطوير (فقدان بيانات التبويبات غير النشطة في نموذج طلب المنحة عند الحفظ) وتم إصلاحه بفضلها — وهي تُشغَّل بالكامل (26 اختبارًا) بنجاح على النسخة الحالية.

### اختبارات يدوية إضافية
تم أيضًا التحقق يدويًا عبر متصفح فعلي من: الاستجابة على شاشة جوال (390px) وسطح المكتب مع عمل القائمة الجانبية المنسدلة، عدم وجود أخطاء JavaScript غير معالجة (Hydration/Runtime) خلال كامل المسار، ونجاح `npm run build` الكامل (فحص TypeScript + ESLint + بناء الإنتاج).

## 10. ملاحظات أمنية وأداء

- كلمات المرور مُشفّرة بـ bcrypt (10 rounds)، ولا تُخزَّن أبدًا كنص صريح.
- الجلسات عبر JWT موقّع بمفتاح سري من متغيرات البيئة، مخزّن في كوكي `httpOnly` (غير قابل للقراءة من JavaScript في المتصفح) و`sameSite=lax`.
- كل عمليات الكتابة (إنشاء/تعديل/حذف/تغيير حالة) تمر عبر Server Actions تتحقق من الجلسة والصلاحية قبل أي وصول لقاعدة البيانات.
- التحقق من صحة المدخلات عبر Zod على الخادم (بالإضافة إلى تحقق HTML الأساسي في الواجهة)، مع رسائل خطأ عربية واضحة.
- رفع الملفات يتحقق من نوع الملف (Whitelist صريح) وحجمه على الخادم قبل الحفظ، ويولّد اسم ملف عشوائيًا لتفادي تعارض الأسماء أو تنفيذ ملفات ضارة.
- لا توجد أسرار أو مفاتيح API داخل الكود المصدري؛ كل القيم الحساسة عبر `.env` (غير مرفوع لأي مستودع).
- استعلامات قاعدة البيانات عبر Prisma (معاملات مُجهّزة تلقائيًا) لمنع حقن SQL.
- صفحات القوائم تدعم البحث والتصفية والترتيب وتقسيم النتائج إلى صفحات لتفادي تحميل بيانات كبيرة دفعة واحدة.

## 11. توسعات مستقبلية مقترحة (اختيارية)

- ربط تنبيهات المواعيد النهائية ببريد إلكتروني (مثلًا عبر Resend المجاني).
- توليد PDF مخصص للتقارير والطلبات من الخادم (بدلًا من طباعة المتصفح).
- الترقية من SQLite إلى PostgreSQL عند الحاجة لتشغيل متعدد الخوادم (يكفي تغيير `provider` في `prisma/schema.prisma` و `DATABASE_URL`).
- سجل تدقيق (Audit Log) مرئي داخل الواجهة (البنية جاهزة في قاعدة البيانات عبر جدول `ActivityLog`).
