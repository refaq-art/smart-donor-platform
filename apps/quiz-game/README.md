# 🎮 حلبة الأسئلة — Arabic Quiz Arena

لعبة أسئلة ومسابقات عربية تفاعلية للعائلة والأصدقاء: لعب فردي، لعب محلي بالتناوب على نفس الجهاز، ولعب جماعي أونلاين عبر غرف خاصة برمز دخول (Room Code) — مع نظام نقاط ديناميكي، صعوبة تكيّفية، إنجازات، لوحة متصدرين، ولوحة تحكم إدارية كاملة لإدارة بنك الأسئلة (يدويًا، أو استيرادًا، أو بمساعدة الذكاء الاصطناعي مع مراجعة بشرية إلزامية قبل النشر).

> **هذا المشروع مستقل تمامًا** عن بقية هذا المستودع (منصة إدارة منح الجمعيات الخيرية في الجذر). يعيش بالكامل داخل `apps/quiz-game` بحزمة `package.json` وقاعدة بيانات وخادم منفصلين، ولا يشارك أي كود أو جداول معها.

## 1. التقنيات المستخدمة ولماذا

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة والخادم | **Next.js 14 (App Router) + React 18 + TypeScript** | يجمع الواجهة و API Routes في مشروع واحد، Server Components لتقليل الجافاسكربت المرسل للعميل، ومناسب جدًا للوحات تحكم ذات منطق خادم كثيف. |
| التصميم | **Tailwind CSS + Framer Motion** | نظام تصميم مرن يدعم RTL بسهولة كاملة، مع مكتبة حركات خفيفة لصنع تجربة لعب حماسية (تأثيرات الإجابة، العدّاد، الفوز...). |
| قاعدة البيانات | **PostgreSQL عبر Prisma ORM** | قاعدة بيانات علائقية قوية تدعم المعاملات (Transactions) اللازمة لحساب النقاط بأمان، مع مخطط قابل للتوسّع بسهولة عبر Prisma. |
| المصادقة | **جلسات JWT موقّعة (jose) + bcrypt** | حل خفيف ومملوك بالكامل للمشروع، يعمل بأمان مع Edge Middleware ومع اتصالات Socket.IO في آنٍ واحد (نفس رمز الجلسة). |
| اللعب الجماعي الفوري | **خادم Next.js مخصّص (server.ts) + Socket.IO** | Next.js القياسي (serverless) لا يدعم اتصالات WebSocket دائمة؛ خادم Node مخصّص يشغّل Next بجانب Socket.IO في نفس العملية، مع تشغيله عبر `tsx` (دون بناء JS منفصل). |
| التحقق من المدخلات | **Zod** | تحقق صارم من كل بيانات العميل قبل لمس قاعدة البيانات، على الخادم فقط. |
| الاستيراد/التصدير | **ExcelJS** | يدعم قراءة وكتابة CSV و XLSX بمكتبة واحدة. |
| الأيقونات | **lucide-react** | مكتبة أيقونات مفتوحة المصدر خفيفة. |

كل هذه التقنيات مفتوحة المصدر ولا تتطلب أي اشتراك مدفوع لتشغيل المشروع محليًا (باستثناء تفعيل مزوّد ذكاء اصطناعي حقيقي اختياريًا).

## 2. بنية المشروع

```
apps/quiz-game/
  server.ts                    # خادم Node مخصّص (Next.js + Socket.IO) — نقطة التشغيل الفعلية
  prisma/
    schema.prisma               # المخطط الكامل لقاعدة البيانات
    seed.ts                     # بيانات تجريبية: تصنيفات، إنجازات، ~140 سؤالًا عربيًا متنوعًا، حساب مسؤول
  src/
    app/                        # صفحات ومسارات Next.js (App Router)
      page.tsx                  # الصفحة الرئيسية
      login/                    # دخول / تسجيل / ضيف
      categories/, leaderboard/, profile/[playerId]/
      play/setup/, play/game/[gameId]/     # اللعب الفردي والمحلي
      room/create/, room/join/, room/[code]/lobby/, room/[code]/play/  # اللعب الجماعي الأونلاين
      admin/                    # لوحة تحكم المسؤول (محمية بـ middleware.ts)
      api/                      # كل REST API Routes
    game-engine/                 # منطق اللعبة الخالص (بدون قاعدة بيانات): النقاط، الصعوبة التكيّفية، اختيار الأسئلة
    server/
      game/                      # تنسيق اللعبة المرتبط بقاعدة البيانات: startGame, submitAnswer, finishGame, state
      room/                      # منطق الغرف: إنشاء/انضمام/بدء/مغادرة
      apiHelpers.ts, rateLimit.ts
    multiplayer/                 # كل ما يخص Socket.IO: الخادم، المصادقة، أحداث الغرفة/الجولة، عميل الاتصال
    achievements/                # تقييم الإنجازات
    components/                  # مكونات واجهة قابلة لإعادة الاستخدام (ui/, game/, layout/, providers/)
    lib/                         # Prisma client, JWT, ثوابت, تحقق Zod, استيراد/تصدير, مزوّدو الذكاء الاصطناعي
  public/
    images/quiz/                 # صور بسيطة (SVG) لأسئلة "تحدي الصور" التجريبية
    sounds/                      # (فارغ) — أضف ملفات mp3 حسب public/sounds/README.md لتفعيل الصوت
```

### فصل الطبقات (مهم جدًا للأمان ولإضافة أنماط لعب جديدة مستقبلًا)

- **`game-engine/`**: منطق اللعبة الخالص (TypeScript بحت، بلا Prisma ولا Next) — حساب النقاط (`scoring.ts`)، الصعوبة التكيّفية (`difficulty.ts`)، اختيار الأسئلة (`questionSelector.ts`)، إعدادات كل نمط لعب (`modes.ts`). هذا الفصل يجعل إضافة نمط لعب جديد أو تعديل معادلة النقاط أمرًا لا يتطلب لمس أي كود واجهة أو قاعدة بيانات.
- **`server/game/`**: يربط المحرك بقاعدة البيانات ويُستخدم من **كلا** الناقلين: REST (اللعب الفردي/المحلي) و Socket.IO (اللعب الجماعي)، فمنطق تسجيل الإجابة وحساب النقاط **مطابق تمامًا** بين الأنماط الثلاثة.
- **الخادم دائمًا هو الحكم**: العميل يرسل فقط اختياره ووقت وصول طلبه؛ الخادم يحسب الوقت الفعلي المنقضي من `Round.startedAt`، يتحقق من صحة الإجابة، ويحسب النقاط — **لا يوجد أي حقل نقاط يُرسله العميل ويُصدَّق عليه مباشرة**.

## 3. التشغيل محليًا

### المتطلبات
- Node.js 18.18+ (يفضَّل 20+)
- قاعدة بيانات PostgreSQL (محلية أو عبر Docker)

### الخطوات

```bash
cd apps/quiz-game
cp .env.example .env
# عدّل DATABASE_URL و SESSION_SECRET في .env

npm install

# شغّل PostgreSQL محليًا (مثال سريع عبر Docker):
docker run --name quiz-postgres -e POSTGRES_USER=quiz -e POSTGRES_PASSWORD=quiz \
  -e POSTGRES_DB=arabic_quiz_arena -p 5432:5432 -d postgres:16

npm run db:push     # ينشئ الجداول من schema.prisma مباشرة (بدون migrations، مناسب للتطوير)
npm run db:seed     # يزرع التصنيفات + ~140 سؤالًا + الإنجازات + حساب مسؤول

npm run dev          # يشغّل خادم Next.js + Socket.IO المخصّص على http://localhost:3000
```

بيانات دخول المسؤول الافتراضية بعد `db:seed`:

```
admin@quiz.local / Admin@12345
```

> ⚠️ غيّر كلمة مرور المسؤول فورًا في أي بيئة غير محلية.

### أوامر مفيدة أخرى

```bash
npm run typecheck    # فحص TypeScript الكامل
npm run build         # بناء إنتاجي (prisma generate + next build)
npm run start          # تشغيل الخادم في وضع الإنتاج (بعد build)
npm run db:reset       # إعادة إنشاء القاعدة بالكامل + إعادة الزرع (⚠️ يحذف كل البيانات)
```

## 4. أنماط اللعب

| النمط | الوصف |
|---|---|
| ⚡ لعبة سريعة | 5 أسئلة من تصنيفات مختلطة، مؤقت مختصر |
| 🎯 كلاسيكي | تصنيف وصعوبة يختارهما اللاعب، 10 أسئلة |
| ⏱️ سباق الوقت | 20 سؤالًا بمؤقت قصير جدًا لكل سؤال |
| 🔥 الإقصاء | يُقصى الأضعف نتيجةً بعد كل جولة (خصم عند الخطأ) حتى يبقى الأقوى |
| 🛡️ تحدي الفرق | فريقان (أحمر/أزرق)، النقاط تُجمع على مستوى الفريق |
| 💪 التحدي | صعوبة تتكيف تلقائيًا حسب أداء اللاعب (فردي فقط) + خصم عند الخطأ |
| 🎉 أجواء العائلة | مؤقت أطول، أجواء مرحة، فرق اختيارية |
| 🌐 غرفة أونلاين | الافتراضي عند إنشاء غرفة؛ يمكن اختيار أي نمط آخر لها أيضًا |
| 📱 محلي | تمرير الجهاز بين عدة لاعبين، كل لاعب يحصل على مؤقت خاص بدوره |

### نظام النقاط (يُحسب بالكامل من الخادم)

```
النقاط = (نقاط السؤال الأساسية × معامل السرعة) + مكافأة السلسلة + مكافأة أول إجابة صحيحة (أونلاين فقط) − خصم الخطأ (إن فُعِّل)
```

- **معامل السرعة**: بين 0.5 و 1.0 حسب نسبة الوقت المتبقي عند الإجابة.
- **مكافأة السلسلة**: 40 نقطة لكل إجابة صحيحة متتالية سابقة، بحد أقصى 400.
- **مكافأة أول إجابة صحيحة**: 200 نقطة إضافية لأول من يجيب صحيحًا في الجولة (اللعب الجماعي فقط).
- **خصم الخطأ**: 200 نقطة (في أنماط الإقصاء والتحدي فقط)، ولا يُطبَّق عند انتهاء الوقت دون إجابة.

### الصعوبة التكيّفية (Adaptive Difficulty)

في نمط "التحدي" (فردي فقط): يراقب النظام آخر 4 إجابات — نسبة صحة 75%+ ترفع الصعوبة درجة، ونسبة 40% أو أقل تخفّضها، ضمن السلّم: سهل ← متوسط ← صعب ← خبير.

## 5. اللعب الجماعي الأونلاين (Socket.IO)

- المضيف ينشئ غرفة (`/room/create`) فيحصل على رمز من 6 أحرف.
- بقية اللاعبين يدخلون الرمز (`/room/join`) وينضمون للـ Lobby حيث يظهر الجميع بصورهم وحالة الاستعداد، ويمكن اختيار الفريق إن كان النمط "تحدي الفرق".
- عند بدء المباراة، تُبث الأسئلة والنتائج فوريًا عبر Socket.IO لكل اللاعبين في الغرفة.
- **معالجة الانقطاع**: عند انقطاع اتصال لاعب لا تتوقف الجولة — الخادم يُجدوِل مؤقتًا يفرض "انتهاء الوقت" تلقائيًا لأي لاعب لم يُجب عند انتهاء وقت الجولة، فتستمر المباراة لبقية اللاعبين دائمًا.
- **ملاحظة على التوسّع**: حالة الغرف والمؤقتات محفوظة في ذاكرة عملية Node واحدة (مناسب لخادم واحد). للتوسّع الأفقي (أكثر من نسخة تشغيل) يلزم لاحقًا استخدام [Redis Adapter](https://socket.io/docs/v4/redis-adapter/) لـ Socket.IO ونقل مؤقتات الجولة لمخزن مشترك.

## 6. إدارة الأسئلة (`/admin`)

- CRUD كامل للأسئلة (6 أنواع: اختيار من متعدد، صح/خطأ، تخمين الكلمة، تخمين الشخصية، الترتيب، تحدي الصور) وللتصنيفات.
- بحث وفلترة حسب النص/التصنيف/الصعوبة/الحالة.
- تفعيل/تعطيل الأسئلة دون حذفها.
- **استيراد/تصدير** بصيغ CSV و Excel و JSON، مع تقرير أخطاء لكل صف قبل الإضافة الفعلية (لا يُضاف أي صف غير صالح).
- **توليد أسئلة بالذكاء الاصطناعي**: يحدد المسؤول التصنيف والصعوبة والنوع والعدد واللغة، فتُنشأ الأسئلة بحالة "بانتظار المراجعة" فقط — **لا تُنشر تلقائيًا أبدًا**. صفحة مراجعة مستقلة (`/admin/ai-generate/review`) تسمح بالقبول أو التعديل أو الرفض لكل سؤال.
  - بدون أي إعداد إضافي، يعمل النظام بمزوّد تجريبي (Mock) يولّد أسئلة عربية حقيقية من بنك مُعَدّ مسبقًا لكل تصنيف (وليس نصوصًا وهمية)، لإثبات أن خط الأنابيب الكامل (توليد → مراجعة → نشر) يعمل فعليًا دون أي مفتاح خارجي.
  - لتفعيل توليد حقيقي وأكثر تنوعًا، اضبط `AI_PROVIDER_BASE_URL` و `AI_PROVIDER_API_KEY` (و`AI_PROVIDER_MODEL` اختياريًا) في `.env` لأي واجهة متوافقة مع OpenAI Chat Completions.

## 7. الأمان

- تحقق Zod من كل مدخلات كل API Route.
- `/admin/**` محمية على مستوى Edge Middleware (يتحقق من دور المستخدم في رمز الجلسة الموقّع قبل الوصول لأي صفحة إدارية).
- كل مسارات الإدارة تتحقق أيضًا من الصلاحية داخل الـ API نفسه (دفاع مزدوج).
- **حساب النقاط بالكامل من جهة الخادم** (راجع القسم 2) — العميل لا يملك أي طريقة لتغيير نتيجته.
- كلمات المرور مُشفّرة بـ bcrypt، والجلسات موقّعة (HMAC) عبر `SESSION_SECRET` وليست قابلة للتزوير من العميل.
- تحديد معدّل الطلبات (Rate Limiting) على مسارات الدخول والتسجيل ولعب الضيف.

## 8. حدود معروفة (Known Limitations)

هذه نقاط واعية ضمن نطاق النسخة الحالية، موثّقة بشفافية بدل التظاهر بأنها غير موجودة:

- **اللعب المحلي (تمرير الجهاز)**: اللاعبون الإضافيون (غير المضيف) يحصلون على سجل لاعب (`Player`) جديد في كل مباراة، لذا إحصائياتهم لا تتراكم عبر عدة مباريات ما لم يُنشئوا حسابًا خاصًا بهم لاحقًا. هذا سلوك متوقع لألعاب "تمرير الجهاز" بلا تسجيل دخول فردي.
- **مزوّد الذكاء الاصطناعي الافتراضي (Mock)**: لا يولّد أسئلة نوع "تحدي الصور" لأنه لا يملك مصدر صور — يوضّح ذلك للمسؤول بدل توليد روابط صور وهمية.
- **حالة الغرف الجماعية**: في الذاكرة (خادم واحد) — راجع ملاحظة التوسّع في القسم 5.
- **الأصوات**: النظام جاهز بالكامل تقنيًا (تشغيل/كتم/موسيقى) لكن لا يتضمن ملفات mp3 فعلية — أضفها حسب `public/sounds/README.md`.

## 9. اختبار يدوي مقترح (Golden Path)

1. افتح `/` → "العب الآن" → اختر تصنيفًا ونمطًا → أجب على الأسئلة → تحقق من ظهور النقاط والسلسلة والنتائج النهائية والإنجازات.
2. افتح المتصفح مرتين (أو جهازين) → أنشئ غرفة من الأول → انضم بالرمز من الثاني → استعدّا وابدآ → تحقق من مزامنة الأسئلة والنقاط لحظيًا بين المتصفحين.
3. سجّل دخولًا كمسؤول (`admin@quiz.local`) → أضف سؤالًا يدويًا → صدّر الأسئلة Excel → عدّل الملف وأضف سؤالًا → استورده وتحقق من تقرير النتائج.
4. من لوحة الإدارة → ولّد 5 أسئلة بالذكاء الاصطناعي (تصنيف "علوم"، اختيار من متعدد) → راجعها → اقبل بعضها وارفض الباقي → تحقق من ظهورها في اللعب الفعلي بعد القبول فقط.
