# منصّة الدورات المجانية

منصة ويب عربية متكاملة (RTL بالكامل) لاستعراض والتسجيل في دورات مجانية ومتنوعة في مجالات مختلفة، مع لوحة مستخدم لمتابعة "دوراتي"، ولوحة إدارة كاملة لإدارة الدورات والمستخدمين والتسجيلات.

> **ملاحظة مهمة عن هذا المجلد**: هذا المستودع يحتوي أيضًا على مشروع منفصل تمامًا في الجذر (منصة إدارة مشاريع ومنح الجمعيات الخيرية). منصة الدورات هذه مشروع مستقل بالكامل — قاعدة بيانات مستقلة، `package.json` مستقل، ويُشغَّل بمعزل تام عن المشروع الآخر. **كل الأوامر في هذا الملف تُنفَّذ من داخل هذا المجلد `courses-platform/`**.

---

## 1. تحليل المتطلبات (ملخص)

- جمهور عام يتصفح دورات مجانية بلا تسجيل دخول، ويُنشئ حسابًا للتسجيل في الدورات ومتابعتها.
- تسجيل آمن يمنع: التسجيل المكرر، تجاوز عدد المقاعد عند التزامن، والوصول غير المصرَّح به.
- لوحة إدارة محمية بالكامل لإدارة الدورات (CRUD + نشر/إخفاء + فتح/إغلاق تسجيل) والمستخدمين والتسجيلات.
- عربي 100%، RTL كامل، متجاوب بالكامل (جوال/تابلت/حاسوب)، حالات تحميل/فراغ/خطأ واضحة.
- قابل للتشغيل المحلي فورًا بدون أي حساب أو خدمة مدفوعة، وقابل للنشر مجانًا بالكامل.

## 2. اختيار التقنيات ولماذا

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة + الخادم | **Next.js 14 (App Router) + React 18 + TypeScript** | إطار مفتوح المصدر ناضج يجمع الواجهة و API/Server Actions في مشروع واحد، يدعم SSR (أداء وSEO أفضل)، مناسب جدًا لمنصة بمنطق خادم كثيف (تسجيل آمن، صلاحيات). |
| التنسيق | **Tailwind CSS** | نظام تصميم مرن يسهّل بناء واجهة حديثة ومتجاوبة وموحّدة بسرعة، ويدعم RTL بسهولة تامة. |
| قاعدة البيانات | **SQLite عبر Prisma ORM** (وTurso/libSQL اختياريًا للإنتاج) | ملف واحد بلا خادم ولا تكلفة، مثالي للتشغيل المحلي الفوري، مع ترقية سلسة لقاعدة بيانات سحابية مجانية عند النشر (Turso) دون تغيير أي كود — Prisma يجرّد طبقة الاتصال بالكامل. |
| المصادقة | **جلسات JWT موقّعة (مكتبة jose) + bcrypt** | حل خفيف ومملوك بالكامل للمشروع، بلا اعتماد على مزوّد مصادقة خارجي، يعمل بأمان مع Edge Middleware لحماية الصفحات فورًا عند الطلب. |
| التحقق من صحة المدخلات | **Zod** | تحقق صارم من كل المدخلات على مستوى الخادم (Server Actions) بجانب الخادم، مع رسائل عربية واضحة — لا اعتماد على تحقق الواجهة وحده. |
| الأيقونات | **lucide-react** | مكتبة أيقونات مفتوحة المصدر خفيفة وشائعة الصيانة. |
| الاختبارات | **Playwright** | اختبارات متصفح حقيقية (E2E) تغطي التدفقات الأساسية فعليًا، مفتوحة المصدر ومجانية بالكامل. |

كل التقنيات المذكورة مفتوحة المصدر ومجانية بالكامل للتشغيل المحلي، ولا تتطلب أي اشتراك.

## 3. البنية المعمارية (Architecture)

```
                        ┌─────────────────────────┐
   المتصفح (RTL/عربي)  ── HTTP ──▶   Next.js App Router (Node.js)  │
                        │  • صفحات عامة (SSR)      │
                        │  • Server Actions (كتابة)│
                        │  • Edge Middleware (حماية)│
                        └───────────┬─────────────┘
                                    │ Prisma ORM
                                    ▼
                        ┌─────────────────────────┐
                        │  SQLite محلي / Turso سحابي│
                        └─────────────────────────┘
```

### فصل الطبقات

- **العرض (UI)**: `src/components/*` (مكوّنات قابلة لإعادة الاستخدام) و`src/app/**/page.tsx` (الصفحات).
- **منطق الخادم (Business Logic)**: `src/app/actions/*.ts` — Server Actions فقط: تحقق صلاحيات، تحقق Zod، عمليات قاعدة البيانات الذرّية، بلا أي منطق فادح داخل المكوّنات.
- **البيانات (Data Layer)**: `prisma/schema.prisma` عبر `src/lib/prisma.ts` (عميل Prisma وحيد بنمط Singleton).
- **طبقة القواعد المشتركة**: `src/lib/*` — حساب حالة التسجيل، الثوابت، التحقق، المصادقة، الأدوات المساعدة — مستخدمة من الواجهة والخادم معًا لضمان اتساق القواعد.

## 4. مخطط قاعدة البيانات (Database Schema)

أربعة نماذج رئيسية (راجع `prisma/schema.prisma` للتفاصيل الكاملة):

```
User                          Category
├─ id (PK)                    ├─ id (PK)
├─ fullName                   ├─ name (unique)
├─ email (unique)             ├─ slug (unique)
├─ phone?                     └─ icon
├─ passwordHash
├─ role (USER | ADMIN)              Course
├─ resetToken (unique)?             ├─ id (PK)
├─ resetTokenExpiresAt?             ├─ title / slug (unique)
└─ createdAt                        ├─ shortDescription / description
                                     ├─ instructorName / providerName
Enrollment                          ├─ categoryId (FK → Category)
├─ id (PK)                          ├─ level / type (ONLINE|IN_PERSON)
├─ userId (FK → User)                ├─ location? / meetingUrl?
├─ courseId (FK → Course)            ├─ startDate / endDate
├─ status (ACTIVE | CANCELLED)       ├─ totalSeats / remainingSeats
├─ enrolledAt / cancelledAt?         ├─ hasCertificate / isPublished
├─ cancelledBy?                      ├─ registrationOpen / isFeatured
│                                    └─ createdById (FK → User)
└─ UNIQUE(userId, courseId)  ← يمنع التسجيل المكرر على مستوى قاعدة البيانات نفسها
```

**القيود والفهارس الأساسية**:
- `@@unique([userId, courseId])` على `Enrollment`: يمنع تسجيل نفس المستخدم في نفس الدورة أكثر من مرة — على مستوى قاعدة البيانات، وليس فقط منطق التطبيق.
- `onDelete: Cascade` على علاقات `Enrollment` بـ `User` و`Course`: حذف مستخدم أو دورة يزيل تسجيلاتها المرتبطة تلقائيًا وبأمان.
- فهارس على `Course.categoryId`، `Course.startDate`، `Course(isPublished, registrationOpen)`، و`Enrollment.courseId` / `Enrollment.userId` / `Enrollment.status` لتسريع الاستعلامات الشائعة (الفلترة، البحث، صفحة "دوراتي").
- الأدوار والحالات (`role`, `level`, `type`, `status`) نصوص (String) لا Enum لأن SQLite لا يدعم Enum في Prisma — القيم الصالحة مركزية في `src/lib/constants.ts`.

## 6. نظام الحسابات والصلاحيات

- **إنشاء حساب / دخول / خروج / استعادة كلمة مرور**: `src/app/actions/auth.ts`، بتحقق Zod كامل ورسائل خطأ عربية موحّدة (لا تكشف عن وجود بريد من عدمه).
- **بيانات المستخدم**: الاسم الكامل، البريد الإلكتروني، رقم الجوال (اختياري)، تاريخ الإنشاء فقط — لا بيانات شخصية غير ضرورية.
- **الحماية**: `src/middleware.ts` يحمي `/account/**` (يتطلب تسجيل دخول) و`/admin/**` (يتطلب دور `ADMIN`) على مستوى الـ Edge، قبل تحميل أي صفحة. كل Server Action حسّاس (تسجيل، إلغاء، عمليات الإدارة) يتحقق من الجلسة **من جديد على الخادم** بغض النظر عن حالة الواجهة — لا اعتماد على إخفاء عناصر الواجهة كحماية وحيدة.
- **استعادة كلمة المرور**: بدون مزوّد بريد مُفعَّل (الوضع الافتراضي)، يظهر رابط الاستعادة مباشرة على الشاشة (ويُطبع في الطرفية) بدل إرسال بريد فعلي — مناسب للتجربة الفورية. عند ضبط `RESEND_API_KEY` (اختياري ومجاني الفئة الأساسية)، يُرسل بريد فعلي.

## 7. نظام التسجيل في الدورات وأمان التزامن (مهم)

عملية التسجيل (`src/app/actions/enrollments.ts`) تمر بخطوات تحقق كاملة على الخادم: تسجيل دخول، عدم وجود تسجيل نشط سابق، الدورة منشورة، التسجيل مفتوح، لم تنتهِ الدورة، ووجود مقاعد متبقية.

### المشكلة: منع تجاوز السعة عند التزامن

ماذا لو ضغط مستخدمان "سجّل الآن" على **آخر مقعد** في اللحظة نفسها؟ يجب ألا يُقبل الطلبان معًا.

### الحل المطبَّق

كل عملية تسجيل تُنفَّذ داخل معاملة قاعدة بيانات واحدة (`prisma.$transaction`)، وخطوتها الحاسمة هي:

```ts
const updated = await tx.course.updateMany({
  where: { id: courseId, remainingSeats: { gt: 0 } }, // شرط يُفحص لحظة الكتابة الفعلية
  data: { remainingSeats: { decrement: 1 } },
});
if (updated.count === 0) throw new EnrollError("عذرًا، اكتملت مقاعد هذه الدورة");
```

**لماذا هذا آمن؟** لأن `updateMany` بشرط `remainingSeats > 0` يُنفَّذ ذرّيًا (Atomic) على مستوى قاعدة البيانات نفسها — إما ينجح ويُنقص المقعد فعليًا (`count = 1`)، أو لا يحدث شيء إطلاقًا (`count = 0`) إن كان طلب آخر قد استهلك آخر مقعد للتو. بما أن SQLite محرك كتابة واحد (Single Writer) وPrisma ينفّذ المعاملات التفاعلية عبر `BEGIN`/`COMMIT` فعلي عليه، **يستحيل** أن ينجح طلبان في قراءة `remainingSeats = 1` ثم خصمها كلاهما في آنٍ واحد — الطلب الثاني سيجد الشرط قد أصبح كاذبًا فور التزام (commit) الطلب الأول. هذا يمنع تجاوز السعة حتى مع طلبين متزامنين تمامًا على آخر مقعد.

**التحقق الفعلي**: `tests/e2e/concurrency.spec.ts` ينشئ دورة بمقعد واحد فقط، ثم يُطلق طلبَي تسجيل من متصفحين منفصلين تمامًا في اللحظة نفسها، ويتحقق مباشرة من قاعدة البيانات أن `remainingSeats = 0` بالضبط وأن هناك تسجيلًا نشطًا واحدًا فقط — لا صفر ولا اثنين.

**منع التسجيل المكرر**: يُمنع أيضًا على مستوى قاعدة البيانات عبر `@@unique([userId, courseId])` على `Enrollment` — لا يمكن إدخال صفّين لنفس المستخدم ونفس الدورة مهما حدث.

**إلغاء التسجيل**: يُعيد المقعد فورًا عبر `remainingSeats: { increment: 1 }` ضمن معاملة واحدة مع تحديث حالة التسجيل، سواء ألغاه المستخدم نفسه أو المسؤول من لوحة الإدارة.

## 8. لوحة الإدارة

محمية بالكامل (`src/app/admin/layout.tsx` يستدعي `requireAdmin()` قبل أي عرض)، وتشمل:

- **لوحة تحكم**: إجمالي المستخدمين، الدورات، التسجيلات، الدورات المفتوحة، الدورات المكتملة، وأحدث التسجيلات.
- **إدارة الدورات**: إضافة/تعديل/حذف، نشر/إخفاء، فتح/إغلاق التسجيل — بكل الحقول المطلوبة (المدرب، الجهة، التصنيف، المستوى، التواريخ، المقاعد، النوع حضوري/أونلاين، الموقع أو رابط الحضور، الشهادة...).
- **إدارة المستخدمين**: قائمة بحث مع عدد الدورات المسجَّل بها كل مستخدم ودوره.
- **إدارة التسجيلات**: بحث وفلترة حسب الدورة/المستخدم/الحالة، مع إمكانية إلغاء تسجيل من الإدارة (يُعيد المقعد تلقائيًا).

**كيفية إنشاء أول حساب مسؤول**: راجع القسم 10 أدناه.

## 9. الأمان — ملخص التطبيق الفعلي

- **Authentication**: جلسات JWT موقّعة (HS256) في كعكة `httpOnly` + `secure` (في الإنتاج) + `sameSite=lax`، مع bcrypt لتجزئة كلمات المرور (10 rounds).
- **Authorization / RBAC**: دوران فقط (`USER`, `ADMIN`)، يُتحقَّق منهما في: Middleware (طبقة أولى)، وفي كل Server Action إداري (طبقة ثانية مستقلة) — **لا يمكن لأي مستخدم عادي تعديل بيانات دورة أو مستخدم آخر عبر استدعاء مباشر لأي Server Action**، لأن كل دالة إدارية تتحقق بنفسها من `session.role === "ADMIN"` بغض النظر عمّا تعرضه الواجهة.
- **Validation**: كل مدخل يمر عبر مخططات Zod صارمة على الخادم (`src/lib/validation.ts`) — الواجهة توفّر تحققًا فوريًا لتجربة أفضل فقط، وليست خط الدفاع الوحيد.
- **SQL Injection**: مستحيل عمليًا لأن كل استعلام يمر عبر Prisma Client (استعلامات مُعامَلة/Parameterized بالكامل، بلا أي SQL خام مبني من مدخلات مستخدم).
- **XSS**: React يُهرّب (escape) كل نص افتراضيًا؛ لا استخدام لـ `dangerouslySetInnerHTML` في كامل المشروع.
- **متغيرات البيئة**: لا سر واحد داخل الكود؛ كل القيم الحسّاسة (`AUTH_SECRET`, `TURSO_AUTH_TOKEN`, `RESEND_API_KEY`) تُقرأ حصرًا من `process.env`، و`.env` مستثنى من Git (`.gitignore`).

## 10. التشغيل المحلي من الصفر

### المتطلبات

- Node.js 18 أو أحدث (تم البناء والاختبار على Node 22).
- npm (مضمَّن مع Node).
- لا حاجة لأي قاعدة بيانات خارجية أو حساب سحابي للتشغيل المحلي.

### الخطوات

```bash
# 0. تأكد أنك داخل هذا المجلد فقط (وليس جذر المستودع)
cd courses-platform

# 1. تثبيت الحزم
npm install

# 2. إعداد متغيرات البيئة
cp .env.example .env
# القيم الافتراضية في .env.example كافية للتشغيل المحلي فورًا بلا أي تعديل.
# للإنتاج: غيّر AUTH_SECRET إلى قيمة عشوائية طويلة (openssl rand -base64 48).

# 3. إنشاء قاعدة البيانات وتطبيق المخطط
npm run db:push

# 4. تعبئة بيانات تجريبية (23 دورة عربية واقعية + حسابات تجريبية)
npm run db:seed

# (الخطوتان 3 و4 معًا في أمر واحد لإعادة الضبط الكامل لاحقًا: npm run db:reset)

# 5. تشغيل المشروع محليًا
npm run dev
```

الآن افتح: **http://localhost:3000**

## 11. النشر المجاني

المنصة مبنية لتعمل بالكامل على خدمات Free Tier سخية بلا أي بطاقة دفع:

| الطبقة | أين | التكلفة |
|---|---|---|
| **الواجهة + الخادم (Next.js)** | **Vercel** (Hobby Plan) | مجاني بالكامل لهذا النوع من المشاريع |
| **قاعدة البيانات** | **Turso** (متوافقة مع SQLite، Free Tier: 500 قاعدة بيانات / 5 غيغابايت) | مجاني |
| **البريد (اختياري)** | **Resend** (Free Tier: 3000 رسالة/شهر) | مجاني، اختياري تمامًا |

### خطوات النشر التفصيلية

**أ) إنشاء قاعدة بيانات Turso**

1. أنشئ حسابًا مجانيًا على [turso.tech](https://turso.tech).
2. ثبّت الأداة: `curl -sSfL https://get.tur.so/install.sh | bash`
3. سجّل دخولك: `turso auth login`
4. أنشئ قاعدة البيانات:
   ```bash
   turso db create courses-platform
   turso db show courses-platform --url      # يعطيك TURSO_DATABASE_URL
   turso db tokens create courses-platform    # يعطيك TURSO_AUTH_TOKEN
   ```
5. طبّق المخطط على القاعدة السحابية من جهازك محليًا (مرة واحدة فقط):
   ```bash
   TURSO_DATABASE_URL="libsql://..." TURSO_AUTH_TOKEN="..." npx prisma db push
   TURSO_DATABASE_URL="libsql://..." TURSO_AUTH_TOKEN="..." npx tsx prisma/seed.ts
   ```

**ب) نشر الواجهة والخادم على Vercel**

1. ادفع المشروع إلى مستودع GitHub (تأكد أن `courses-platform/` هو **جذر المشروع المستورد في Vercel** — اضبط "Root Directory" في إعدادات المشروع على `courses-platform` إن كان جزءًا من مستودع أكبر).
2. من [vercel.com](https://vercel.com) اربط المستودع، واضبط:
   - **Root Directory**: `courses-platform`
   - **Build Command**: افتراضي (`npm run build`)
3. أضف متغيرات البيئة التالية في إعدادات المشروع (Environment Variables):

   | المتغير | القيمة | ملاحظة |
   |---|---|---|
   | `AUTH_SECRET` | نص عشوائي طويل (`openssl rand -base64 48`) | **إلزامي** |
   | `TURSO_DATABASE_URL` | من الخطوة (أ) | **إلزامي للإنتاج** — بدونه يُستخدم SQLite محلي غير دائم على Vercel |
   | `TURSO_AUTH_TOKEN` | من الخطوة (أ) | **إلزامي للإنتاج** |
   | `NEXT_PUBLIC_SITE_URL` | رابط النشر النهائي (مثلًا `https://your-app.vercel.app`) | موصى به (يُستخدم في روابط استعادة كلمة المرور والـ sitemap) |
   | `RESEND_API_KEY` | مفتاح Resend | اختياري — بدونه تعمل استعادة كلمة المرور بوضع العرض المباشر على الشاشة |
   | `RESEND_FROM_EMAIL` | بريد مُرسِل مُتحقَّق منه في Resend | اختياري، مطلوب فقط مع `RESEND_API_KEY` |

4. اضغط **Deploy**. عند أول نشر، لا حاجة لأي أمر إضافي — المشروع يقرأ `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` تلقائيًا (`src/lib/prisma.ts`) ويتصل بالقاعدة السحابية التي هيّأتها في الخطوة (أ).

**ج) بعد النشر**

- سجّل دخولك بحساب `admin@example.com` (من بيانات البذر التي طبّقتها في الخطوة أ) لإدارة المنصة فورًا، أو أنشئ حسابك الخاص عبر `/register` ثم رقِّه بأمر `make-admin` **محليًا مع الإشارة لقاعدة Turso**:
  ```bash
  TURSO_DATABASE_URL="libsql://..." TURSO_AUTH_TOKEN="..." npm run make-admin -- your-email@example.com
  ```
- **أين تُحفَظ الصور؟** حقل صورة غلاف الدورة هو رابط خارجي (URL) يُدخله المسؤول يدويًا — لا حاجة لخدمة تخزين ملفات؛ بلا صورة تظهر بطاقة غلاف افتراضية متدرّجة الألوان تلقائيًا.
